# tools/

Developer and CI tooling. Everything here runs through the root `Makefile`; you rarely call it directly.

| Path | What it is |
|---|---|
| `scripts/` | Plain Bash scripts (`set -euo pipefail`, Linux x64), plus stdlib-only Python run with `python3 -I`. No sudo, nothing installed outside your home directory. |
| `scripts/setup-flutter.sh` | Installs the Flutter SDK pinned in `.fvmrc` into `~/development/flutter-<version>`: the official stable archive, sha256-checked against Flutter's release index, analytics disabled. Skips if already installed, after checking that the SDK there really is the pinned version (`bin/cache/flutter.version.json`); any other version is an error, never silently used. Used by `make toolchain-flutter`. |
| `scripts/setup-dotnet.sh` | Installs the .NET SDK pinned in `backend/global.json` into `~/.dotnet` (or the directory given as argument). Takes the SDK tarball URL and sha512 from Microsoft's release metadata (`releases.json`), accepts only `https://builds.dotnet.microsoft.com/`, and checks the sha512 *before* extracting; no hash or no archive is a hard failure. Then merges into the install dir like `dotnet-install.sh` does (existing versioned folders only gain missing files, `dotnet` muxer replaced, `sdk/<version>` moved in last). Skips if that SDK (or a newer patch in the same feature band) is present. Never touches a system .NET. Used by `make toolchain-dotnet`. |
| `scripts/doctor.sh` | Prints tool versions, free disk and RAM, and fails if the pinned SDKs (Flutter, .NET, JDK 21 + Android SDK packages and licences) or Docker (daemon access, Compose v2) are missing; warns if the contract tool images aren't pulled yet. Used by `make doctor`. |
| `scripts/setup-android.sh` | `setup-android.sh <java-home> <android-home>`: installs Temurin JDK 21 (`~/development/jdk-<build>`) and the Android SDK (`~/development/android-sdk`): cmdline-tools 22.0 from a sha256-pinned archive, then `sdkmanager` (checksums from Google's repository XML) for the packages in `android-sdk-packages.txt` (platform-tools, platforms 36 + 35, build-tools 36.0.0, NDK 28.2, CMake 3.22.1), and accepts the SDK licences (S06 plan D19). Checks for 8 GB free before downloading. Skips whatever is present, with no network access when nothing is missing; a JDK or cmdline-tools of another version is an error. Used by `make toolchain-android`. `setup-android.sh --sdk-only <android-home>` (`make toolchain-android-sdk`, CI) installs only the missing SDK packages into an existing SDK (the runner's) with the JDK at `$JAVA_HOME`: the SDK's own sdkmanager first, the pinned cmdline-tools 22.0 if that fails. |
| `scripts/build-android.sh` | Builds one flavor (`FLAVOR`, `MODE`, `BUILD_NUMBER` from `make build-android`). Release: an arm64 APK + an AAB, the APK checked by `apk_hardening_check.py`. It verifies the signer (`apksigner` for the APK, `jarsigner -verify -strict` for the AAB): with the release key (environment or `~/.fitness-buddy/keys/release.env`) it must be the pinned certificate; without one it sets `FB_ALLOW_DEBUG_SIGNING=1` and renames the outputs `*-debugkey.*`. Always stops the Gradle daemons. |
| `scripts/apk_hardening_check.py` | Release APK hardening check (Python 3 stdlib, run with `python3 -I`), from `aapt2 dump` output, fail-closed: `debuggable` and `usesCleartextTraffic` absent or false, network security config with one `base-config cleartextTrafficPermitted=false`, system CAs only, no `domain-config` (dev: only 127.0.0.1/localhost); any value or element it doesn't know fails. Also checks captured dumps (`--dumps`) and writes them (`--capture`). |
| `scripts/apk-hardening-selftest.sh` | `make apk-hardening-selftest` (part of `make check`): runs the check on the fixtures in `scripts/testdata/apk-hardening/` (real staging/prod dumps and bad variants derived from them); each bad one must fail with its expected message. No Android SDK needed. |
| `scripts/android-sdk-packages.txt` | The pinned Android SDK packages: installed by `setup-android.sh`, reported by `doctor.sh`, build-tools version used by `build-android.sh`. |
| `scripts/android-release-key.sh` | One-off: creates the release keystore and `release.env` in `~/.fitness-buddy/keys` (mode 600, dir 700), never overwrites, prints only the certificate SHA-256. See `docs/runbooks/android-signing.md`. |
| `scripts/cold-start.sh` | `cold-start.sh <application-id> [runs]`: one warm-up, then `runs` × `am start -S -W` over adb. Prints each `TotalTime`, the median and p90, the device and its build (S06 plan D20). Used by `make cold-start`. |
| `scripts/ci-status.sh` | `ci-status.sh <sha> [timeout-min]`: waits for the required check `ci` (`.github/workflows/ci.yml`) on a pushed commit and prints every check run with its URL. Anonymous GitHub API (public repo, 60 requests/hour; `GITHUB_TOKEN`/`GH_TOKEN` used if set). First poll after 3 min (capped so at least one poll happens before the timeout), then every 60 s, sleeps through rate limits. Only check runs from GitHub Actions count; if a commit has several `ci` runs, all must be finished and the newest decides. Exit 0 = `ci` passed, 1 = failed, 2 = timed out (default 25 min). Used in the merge flow before pushing a SHA to `main`. |
| `contract-tools/compose.yaml` | The API contract tools as Docker images pinned by tag + digest: Redocly CLI (bundle), Spectral (lint), oasdiff (breaking + conformance). Every service runs with no network, as your uid:gid, with the repo mounted at `/work`, a read-only root filesystem and no capabilities; telemetry is off. The Makefile runs them with `docker compose run --rm -T` and exports `UID`, `GID`, `REPO_ROOT`. Dependabot (`docker-compose`) proposes bumps. See `contracts/README.md`. |
| `scripts/contract-selftest.sh` | Proves the contract checks still work: every Spectral fixture in `contracts/selftest/spectral/` fails with exactly the rule named on its `# expect:` line, the breaking gate fails a removed field and passes additive changes, and the conformance check fails a renamed field with its readable message. Used by `make contract-selftest`. |
| `scripts/contract-breaking.sh` | Breaking-change gate (`oasdiff breaking`). Base: `CONTRACT_BASE_REF`, else the newest `contracts-v*` tag (both block), else (pre-release) the merge-base with `origin/main`, reported as a notice that passes. Writes a job-summary table in GitHub Actions. `--files <base> <revision>` compares two files (self-test). Used by `make contract-breaking`. |
| `scripts/contract-conformance.sh` | `contract-conformance.sh [<contract> [<server-doc>]]`: `oasdiff changelog --fail-on INFO` between the contract and the server's build-time OpenAPI document; any API difference fails with a readable message and a fix hint (annotations in GitHub Actions). Used by `make contract-conformance`. |
| `scripts/gen-dart.sh` | Regenerates the Dart API client in `packages/fb_api_client` from `contracts/openapi.yaml` (and the generator fixture into its `test/generated/`): copies both specs into the package's `.dart_tool/fb_gen/` with `format: date` lines stripped (fails if the format survives in another spelling), deletes the generated folders, runs swagger_parser, writes a no-lint `analysis_options.yaml` into each generated folder, runs build_runner and `dart format`. Deterministic. Used by `make gen-dart` (part of `make gen`) and `make gen-check`. |
| `app_check/` | Architecture checks for `apps/mobile/lib` (Dart package `fb_app_check`, workspace member, no dependencies): feature and layer import boundaries, no raw user-facing strings, no left/right layout. Used by `make app-check`, part of `make check-dart`. See `app_check/README.md`. |
| `catalog/` | The food catalog tool (Dart package `fb_catalog`, workspace member): USDA import (`import-usda`, from `data/usda_selection.yaml` to the committed `data/usda/extract.jsonl`), reference-dish validation against `data/schema/` (`validate`), per-100 g compute through `fb_domain`, the prototype pack (`build`, FTS5 trigram), `query` and the must-cover `coverage` report. Used by `make catalog` and `make catalog-usda`. See `catalog/README.md`. |
| `trace/` | Requirement traceability report (Dart package `fb_trace`, workspace member): spec IDs vs tagged tests, per release. Used by `make trace`. See `trace/README.md`. |

Later steps add more Dart tools here, see `technical-planning/10-engineering-practices.md` §1.

Conventions for scripts: take paths as arguments (the Makefile passes them), print clear `name: error: …` messages to stderr, are safe to re-run, and keep downloads in a fresh temp directory that is removed on exit.
