### 1. Summary
After B09a, `POST /v1/buddy/interpret` (prompt `interpret-v2`) returns eleven new typed public intents next to B08's five: diary edit, delete, copy and ambiguous reference; memory change; batch, batch portion and batch close; personal food; saved-meal log and saved-meal create. `foodLog` and `weighIn` gain a nullable structured `dateHint`. The model links mentions to ephemeral list indexes. Server code maps them to request IDs and decides ambiguity per AI-091 (TD-091), so the provider still never sees an ID, grams or a nutrient. `fb_domain`'s decoder degrades unknown kinds to `unrecognized` instead of failing the message (`04` §4.2). After B09b, `buddy_eval` feeds API responses into A21's `ProposalEvaluation` with real catalog facts. It reports AQ-02 to AQ-08 and AQ-10 per language (en/ar/arabizi), and CI gates the M3 thresholds. The new kinds are graded at interpretation level until A25–A27 add their engines.

- **TD-091** · Buddy reference policy is server code over model-linked candidates. The model links mentions to ephemeral list indexes (`ref`) with scope one|all and day/slot hints. The server maps indexes to request IDs and decides:
  - all → every ref;
  - one + 1 ref → target;
  - >1 refs with a date/slot qualifier, or >1 in the newest (date, slot) → `ambiguousReference` (candidates + operation + patch);
  - >1 unqualified → newest;
  - 0 refs + hint → empty targets for the app's local lookup;
  - 0 refs, no hint → clarify `referenceNotFound`.

  The model never emits ambiguity. | Proposed (B09a D7) | AI-091 is deterministic and testable; no IDs to the provider (AC-041); the chip tap needs no second call | Alternatives: the model decides ambiguity/IDs; app-side NLP | B09a D6/D7, `06` §3.
- **TD-092** · User-stated nutrition figures may be transcribed, never produced. A Buddy intent may carry nutrient values only if each equals a numeric token of the user's message (literal guard, digit/decimal normalization). They are user data (ⓨ "from your message"), reviewed in the personal-food form with FD-012 highlighting, like label extraction. All other model nutrition stays forbidden, except the badged estimate. | Proposed (B09a D9; owner FYI) | Clarifies the scope of rule 1 / TD-009 consistently with label scans (`06` §8) | Alternative: drop stated values (components/form only) | B09a D9, A27.

### 3. Design

**3.1 Contract diff (`contracts/openapi/modules/buddy.yaml`; bundle + `fb_api_client` regenerated)**
- Request: **no new property** (fingerprints unchanged). Descriptions only: `BuddyRecentEntry` "ordered newest first; ≤ 30, about 3 days; only date/slot/name are forwarded"; `BuddyMemory.kind` "open; `memoryKind` codes recommended"; the endpoint description adds "unknown intent kinds must degrade (04 §4.2)" and the clarify reason vocabulary (`unclear`, `unsupported`, `offTopic`, `invalidInterpretation`, `unmatchedFood`, **`referenceNotFound`**).
- **Additive on existing schemas (group A commit, PA3):** `BuddyFoodLog.dateHint` and `BuddyWeighIn.dateHint`: `string|null`, D8 pattern.
- Shared new schemas: `BuddyDayHint {dateHint: string|null (D8 pattern), slotHint: string|null, timeHint: string|null}` · `BuddyEntryReference {mention: string, dateHint, slotHint, scope: enum[one, all]}` · `BuddyDiaryPatch {amount: BuddyAmount|null, replacement: BuddyFoodItem|null, move: BuddyDayHint|null}` (≥ 1 non-null; `amount` is absolute, PA15) · `BuddyPortion {amount: BuddyAmount|null, share: BuddyShare|null}` (≥ 1 non-null) · `BuddyStatedNutrients {basis: enum[per100g, perServing], servingG, kcal, proteinG, carbsG, fatG, fiberG: number|null}` (description: "transcribed user figures, TD-092").
- **Group A (A25):** `BuddyDiaryEdit {kind: diaryEdit, language, script, targets: uuid[] ≤30, reference: BuddyEntryReference, patch: BuddyDiaryPatch}` · `BuddyDiaryDelete {kind: diaryDelete, language, script, targets, reference}` · `BuddyAmbiguousReference {kind: ambiguousReference, language, script, operation: enum[edit, delete], candidates: uuid[] 2..30, reference, patch: BuddyDiaryPatch|null}` · `BuddyDiaryCopy {kind: diaryCopy, language, script, source: BuddyDayHint, target: BuddyDayHint}`.
- **Group B (A26):** `BuddyMemoryChange {kind: memoryChange, language, script, operation, memoryKind, subject: string|null, dimension: enum|null, value: string|null, amount: BuddyAmount|null, food: BuddyFoodItem|null}`.
- **Group C (A27):** `BuddyBatch {kind: batch, language, script, name: string|null, ingredients: BuddyFoodItem[] 1..30, cookedWeight: BuddyAmount|null, path: enum[quick, leftovers]|null, eatenNow: BuddyPortion|null, timeHint, slotHint, dateHint}` · `BuddyBatchPortion {kind: batchPortion, …, batchId: uuid, portion: BuddyPortion|null, rest: boolean, timeHint, slotHint, dateHint}` (exactly one of portion or rest) · `BuddyBatchClose {kind: batchClose, …, batchId}` · `BuddyPersonalFoodCreate {kind: personalFoodCreate, …, name, aliases: string[] ≤5, components: BuddyFoodItem[] ≤30, stated: BuddyStatedNutrients|null}` · `BuddySavedMealLog {kind: savedMealLog, …, savedMealId: uuid, timeHint, slotHint, dateHint, share: BuddyShare|null}` · `BuddySavedMealCreate {kind: savedMealCreate, …, name, activeProposal: uuid|null, targets: uuid[] ≤30, source: BuddyDayHint|null}` (exactly one source).
- `BuddyIntent.oneOf` + `discriminator.mapping` gain all eleven. All enums are camelCase. Names avoid clashing with the request schemas `BuddyMemory`/`BuddyPersonalFood`.

**3.2 Backend (Buddy module only; Catalog via `Catalog.Contracts`; no schema/migration; Usage/ledger unchanged)**
- `Domain/BuddyInterpretation.cs`: public DTOs for 3.1 (WP1). `Domain/ParsedMessage.cs`: v2 internal records (D5 groups; `ParsedKind` +10, no ambiguity kind) (WP2).
- `Infrastructure/ProductionProtocol.cs`: `Version = "interpret-v2"`, v2 resource/schema, and the projection with `ref` indexes (D6). Semantic `Valid(...)` per kind returns **closed diagnostic codes** (PA13): `refRange`, `mixedGroups`, `statedNotLiteral`, `dayHint` (plus B08's existing outcome codes). They are logged as codes only, never content. Bounds: intents ≤ 10, items ≤ 30, aliases ≤ 5, strings ≤ 200.
- **Not invalid output, so no repair** (PA8): `fromActiveProposal` with no `request.activeProposal`, `batchPortion`/`batchClose` with an empty `openBatches` or a null `listRef`, and `savedMealLog` with no matching saved meal (null `listRef`). All of these map directly to `clarify` `referenceNotFound`.
- `Prompts/interpret-v2.txt`: the kind rules (refs/scope/qualifiers, day grammar incl. transcribed `date:`, slot rule, `dateHint` on food/weigh-in, memory, batch vs reference dish DY-045, saved meals, "this", **relative amount edits ("add 50g", "double it") → `clarify` `unsupported`**, PA15; **a nameless "save this" → `clarify`, `savedMealCreate.name` is never null**; a copy without a source slot → `clarify` in R1; "ate the rest" → `batchPortion` with `rest: true`; a medical message stays `medical`, WP1 review). B08's food rules are unchanged.
- `Application/ResolveInterpretation.cs` is split into a dispatcher + `ResolveFoods` (B08 code, moved) + `ResolveReferences` (D6/D7, edits/deletes/copy/saved meals) + `ResolveCreations` (memory, batch, batch portion/close, personal food). It uses `ProductionProtocol.Version`, never a literal (PA10).
- Unchanged guarantees: no writes or totals (`03` §5.3); replay stores the response only (24 h, RLS, erasure); logs carry only model/version/outcome/timing/tokens/cost and the PA13 codes.

**3.3 App package (`fb_domain`, WP1 only):** `interpretation_decoder.dart` gets D4 and nothing else. Coverage stays at 100 %; the amended A21 test is listed in the Progress log.

**3.4 Eval**
- B09a: `cases/b09.yaml` (v2 `parsed` fixture + `context` + `expected` per kind, with stable case-local IDs). `bin/public_eval.dart` sends the case context and runs both files. `lib/public_eval.dart` gains per-kind graders and the **ID-provenance check** (PA5). `check-buddy-eval.py` gets per-file required IDs, per-kind check sets and the ≥ ¼ AR/Arabizi rule. The report is `backend/artifacts/buddy/eval-offline.json`.
- B09b: `buddy_eval` gains the workspace dependency `fb_domain`. `lib/aq_metrics.dart` provides the case → `ProposalRequest` adapter (D16) → `ProposalEvaluation.evaluate`, and AQ-02/03/04/05/06/07/08/10 with breakdown keys **`en`/`ar`/`arabizi`**. Cases gain `expectedKcal` (catalog-release-stamped), `ambiguous: true|false` and `savedDefaults`. The real-catalog run is in `Persistence.Tests`.

**3.5 Rules respected:** AI interprets and code computes (the model links/extracts/transcribes; IDs, ambiguity, ranges and arithmetic are code). Single writer: no write path. Contract-first: WP1 merges before any server code. Module boundaries: Buddy → Catalog.Contracts only. Privacy: no identity/IDs/grams/nutrients to the provider, no content in logs. Local-first: unaffected.
