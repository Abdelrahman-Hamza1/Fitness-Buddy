**Deviations (simplest sound option):**
- **No inline set editing on the workout card** (WO-030 "same inline editing as food proposals"): the card shows sets, PR marks and Buddy's notes; WO-033 picks (≤ 3 library matches, "New exercise", "Leave it out") are the only edits; sets are edited in the workout form after saving. A new custom exercise gets type from its sets, equipment `other`, no muscle.
- **PR hints** only for exercises with earlier sets (a first session isn't marked) and only heaviest/e1RM (not reps-at-weight).
- **Import rows can be accepted, not fixed, on the card**: "Include" per flagged row (blocked rows stay out); fixing a value is done after import in the weight history. Measurement imports use a small sibling check (range, future, duplicate ± 0.1 same day, jump > 15 % / 5 points within 14 days). Picks and accepts live in memory (a restart asks again).
- **Measurement card**: built-in kinds or a still-existing custom type (shown without its name: the server sends built-ins only).
- **Photos are never re-encoded**: a picture that isn't a ≤ 1024 px JPEG after the native resize (e.g. a transparent PNG) is refused with a plain message; no image codec dependency. Metadata segments (APP1–APP15, COM, before and between scans) and bytes after EOI are stripped in Dart before upload. The photo is memory-only: the files the picker hands over are listed as owned and deleted right after reading (leftovers on the next Buddy bar open); the plugin's own gallery copy in its cache folder isn't known to the app and is left to the OS cache, so a turn resumed after a restart goes without it (its cards stay estimates through the checkpoint `photo` flag).
- **Label review screen = the new-food form** (FD-041) with highlighted fields ("Check this against the label", supporting text, not error red) and an info banner listing other nutrients (not stored: no fields). Saving is the confirmation (the form's normal Undo); no proposal row.
- **New dependency** `image_picker` 1.2.4 (exact pin; flutter.dev, BSD-3, Android + iOS; transitive: `image_picker_*`, `file_selector_*` platform packages, `flutter_plugin_android_lifecycle`, all flutter.dev). The Android plugin asks the CAMERA permission at runtime (the app declares it for the scanner).
