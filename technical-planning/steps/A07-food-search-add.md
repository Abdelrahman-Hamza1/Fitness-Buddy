**Goal.** Find any food in the offline catalog, your own foods or your history, pick an amount in any unit, and log it with one tap and an undo. This is the manual path that must always work, offline included.

**Spec:** FD-020 (offline part), FD-021, FD-022, FD-023, FD-010, FD-011, FD-060, FD-062, LC-005, LC-011, AI-048, UX-006 (structure), OF-01 (food parts) · **Decisions:** TD-009, D-080

## Scope
- **Search service** (data + domain): FTS5 over `catalog.db` + personal foods + recent/history items, query normalization via `fb_text`, **ranking & de-duplication** (`07` §5.2): yours/recent → verified → reference dishes, one row per distinct food, ties by usage count.
- **Search UI:** one box (EN, Arabic script, Arabizi via listed aliases), instant results as you type, recent foods when empty, food rows with source badge and kcal per default serving.
- **Food detail:** names (interface language + the other on details when present, LC-005), nutrients per 100 g and per serving, state, source badge, sanity status.
- **Amount & unit picker:** number pad, units incl. food-specific servings and local portion words, any unit accepted (LC-011), **defaults to the last used amount for that food** (FD-022). Raw/cooked state choice when relevant, with a yield note (FD-062).
- **Add = direct action:** a `ChangeSet` → applied → undo snackbar (AI-048). Slot assigned automatically, editable.
- Search performance budget and an empty/no-results state ("Try another name, or create your own food" → A09).

## Out of scope
- Online catalog search (A24, B07), barcode (A28), personal food creation (A09).

### 1. Summary
After A07 the user can open **Add food** (from Today's empty state until A08 adds "+" per slot), type in English, Arabic or Arabizi, and see results instantly from the offline pack and their own history. Results are ranked and de-duplicated (one row per distinct food, theirs first), each with a source badge and kcal per default serving. Recent foods show when the box is empty. A tap opens the **food sheet**: names (EN · AR), nutrients for the chosen amount and per 100 g, state, badge, sanity note, a number pad, unit chips (food portions first, any unit accepted), a raw/cooked choice that switches to the food in the weighed state with a yield note when relevant, and the slot. The amount defaults to the last one used for that food. **Add** is one direct action (`LogEntries`, origin `direct`), followed by a 5 s undo snackbar. Pure search logic sits in `fb_domain`/`fb_text`, data in `core/catalog` + the diary repository, and orchestration in the new `features/foods/` (the feature `03` §3 names for search).

| D3 | **Candidate generation, deterministic (PA1, PA2).** Query: `parseQuantity` (D7), then `normalizeKey` → key and tokens (at most 6 tokens go into the SQL; all of them are matched in Dart). Three passes per keystroke over `names` (food and dish targets only, since A05b put exercises in `names`). **(a) Exact/prefix** through the `names.key` index: `key = :q OR (key >= :q AND key < :q || char(1114111))`, with no ranking cap; a safety bound of 500 rows `ORDER BY length(key), key, rowid`. **(b) Tokens:** an FTS5 trigram phrase for tokens of ≥ 3 runes, word-prefix `LIKE` for shorter ones (`رز`, `pi`), plus the fuzzy-corrected words from (c) as extra phrases. Each row gets `word_hits` = Σ over tokens of `(' ' || key) LIKE '% ' || t || '%'`, computed in SQL, then `ORDER BY word_hits DESC, length(key), key, rowid LIMIT 300`. So the cap always cuts the weakest rows, and exact/prefix rows never compete for it. **(c) Fuzzy (FD-020 typos):** an in-memory **deletion-neighbourhood index** (SymSpell-style, pure `FuzzyIndex` in `fb_domain`) over the vocabulary = the distinct words of every pack name key plus the history names. It is built lazily once per pack version, and again per history emission for history words. Deletes go to distance 1 for words of 4–6 runes and 2 for ≥ 7, verified by optimal-string-alignment distance, so transpositions count (`rcie` → rice, `chiken` → chicken). If the vocabulary exceeds 30k words, distance 2 is dropped (memory bound). **When fuzzy runs:** for every token of ≥ 4 runes that is **not a prefix of any vocabulary word**, whatever other tokens or names hit. The up-to-5 nearest words (distance ↑, length difference ↑, word ↑) join pass (b). Fuzzy covers whole words only (a half-typed word just waits for more letters). **Target selection:** every target with strength ≥ `prefix`, then the other targets by (strength ↓, word_hits ↓, nameLen ↑, target ↑) up to 60 targets in total, **plus every history-matched target, uncapped** (D6). Arabizi stays alias-based (FD-024's skeleton is R2) | A cap only stays safe if its order is defined: exact/prefix and history can never be cut. FTS trigrams can't retrieve a transposition (`rcie` shares no trigram with `rice`), but a deletion index can, with microsecond lookups. Running fuzzy per unknown word instead of "when nothing hit" stops unrelated substring hits from hiding the intended food |

### 3. Design

**3.1 `fb_text`** (WP1): `identityKey(String)` (D4) in `normalize/normalizer.dart`: steps 1–6 and 8 of `normalizeKey` plus step 7 only for Arabic letters (no Latin repeat-collapse). **3.2 `fb_domain`** (WP1, pure, exported, no `fb_text` dependency: inputs are already-normalized keys)
```
src/food/search/name_matcher.dart     MatchStrength {partial, substring, fuzzy, words, prefix, exact} (ordered, + isGood);
                                      NameMatcher.match(queryKey, tokens, nameKey, {FuzzyIndex?}) → MatchStrength?; osaDistance(a, b, max)
src/food/search/fuzzy_index.dart      FuzzyIndex.build(Iterable<String> words, {maxWords = 30000}); isWordPrefix(token);
                                      corrections(token, {limit = 5}) → List<String> (D3: deletes d1 for 4–6 runes, d2 for ≥ 7, OSA-verified)
src/food/search/search_candidate.dart SourceTier {personal, history, database, reference}; SearchCandidate<T>(keys, tier, strength,
                                      uses, lastUsedHlc?, nameLength, isDefaultVariant, id, payload: T)
src/food/search/food_search_ranker.dart FoodSearchRanker.rank<T>(candidates, {limit = 30}) → List<T>: D4 merge (union-find,

src/food/portion/default_portion.dart DefaultPortion.choose(FoodMeasures, {Quantity? lastUsed, ParsedAmount? parsed}) → Quantity (D8)
src/food/portion/unit_options.dart    UnitOptions.of(FoodMeasures) → List<String> unit codes (D8 order, resolvable only)
src/food/portion/state_sibling.dart   StateSibling.choose(picked: (nameKey, state, yieldGroup), groupFoods, stated) → ordered list (D9)
src/diary/food_history.dart           FoodHistoryItem (D6 fields; pack metadata nullable) + derivedServing → ServingUnit? (basis-aware)
```
