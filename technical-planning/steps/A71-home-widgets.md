# A71 — Home-screen widgets (app, Android)

| Track | Depends on | Size | Owner | Status |
|---|---|---|---|---|
| App | A70 (`BuddyEntry` voice mode, for the Speak button only) | M | Claude (Opus build), Codex review (code + security) | ✅ |

**Goal.** Three Android home-screen widgets that show today at a glance and open the app (UX-080, UX-082–085, D-101). Design: the owner's canvas (boards "On the home screen", "Small, numbers only", "Sizes and states"; the dark look is the pick; https://claude.ai/artifact/J4SeT5YnJzhY8McY4PLx4k).

## Scope
1. **Medium 4 × 2:** calories-left ring ("1,240 kcal left", over target in the neutral over tone), "eaten of target", protein/carbs/fat/fiber bars against targets (macro colours), buttons Speak · Ask · Weigh.
2. **Small 2 × 2:** ring + protein bar. **Small 2 × 1:** Speak · Ask icons.
3. Light/dark follow the phone (Ink & Sky palettes). Native Android widget (Jetpack Glance or RemoteViews, chosen in the plan) fed by the app through a bridge plugin (chosen in the plan); the widget never opens the database.
4. Taps only open the app (UX-083): Speak → Buddy listening (A70 `BuddyEntry.voice`; until A70 merges, keyboard), Ask → Buddy keyboard, Weigh → weigh-in, numbers → Today. Explicit intents only: no new exported deep-link intent filter; the only new exported component is the widget receiver the platform requires.
5. Refresh on every change to today's intake/targets and at midnight; no targets → calories eaten. Profile switch shows the active profile; sign-out / remove / delete clears the numbers. "Hide numbers" setting (buttons only).
6. Tests (lean): the snapshot the app writes (numbers, hidden, cleared) and the tap routing.

## Exit criteria
1. On the A55: add each widget, log a meal → numbers update; tap each button → the right screen; hide numbers; sign out → numbers gone.
2. CI green; Codex code + security review passed.

| # | Decision | Why |
|---|---|---|
| D1 | **No bridge plugin: a small own platform channel** (`fitness_buddy/home_widget`, like `SessionStorageDurability`). `home_widget` 0.10.0 (BSD-3, maintained, AGP 9 OK) was checked and rejected: it pulls `glance-appwidget` (+ Compose runtime), WorkManager and coroutines into the APK, and with them WorkManager's exported diagnostics receiver and extra permissions, for features we don't use (Glance rendering, background callbacks, configure). Our needs are four calls (save, clear-if, refresh, take launch action) and ~150 lines of Kotlin. No new pub or Gradle dependency, so the pub-lock check and the Maven pins are untouched. iOS: the Dart port is a no-op off Android (widgets are Android-only in R1, D-081). | Fewer deps, smaller attack surface, simplest |
| D2 | **Rendering: XML `RemoteViews`** (no Glance: it needs the Compose compiler plugin in our Gradle build). The ring is a determinate `ProgressBar` with a `ring` shape drawable (`useLevel`), the macro bars horizontal `ProgressBar`s with `scale` drawables; over target swaps to a sibling bar in the over tone (visibility only). **Every colour is a resource** (`values/` + `values-night/`, copied from Ink & Sky, checked by a Dart test against `FbPalette`), so light/dark follow the phone without a redraw. Vector icons from AOSP/Material (Apache-2.0) and the Momentum mark (verbatim brand geometry). | Night mode for free; compiles with plain AGP |
| D3 | **Snapshot = flat key/values in the app's private SharedPreferences file `fb_home_widget`** (not `FlutterSharedPreferences`; excluded from backup already: `backup_rules` excludes every domain and `data_extraction_rules` is an allow-list of the profile DB). Content: schema `v`, `state` (`numbers` / `hidden` / `signedOut`), a profile tag (FNV-1a of the profile key, as notifications), and **two day blocks, today and tomorrow** (date, mode `targets`/`eaten`, formatted kcal number, caption, ring 0–1000, over, "eaten / target", per macro the formatted value and bar 0–1000 + over). Numbers only: no food names, no user text. Formatted in Dart from ARB strings (English, D-080); fixed words (Today, macro names, Speak/Ask/Weigh, "What did you eat?", "Open Fitness Buddy", picker labels) are Android string resources, because the widget must render before the app ever wrote (deviation from "all strings in ARB", unavoidable for native widget UI). | Widget never opens the DB; minimal content |
| D4 | **Midnight:** the widget picks the block whose date is the phone's local date; tomorrow's block is computed by the app now (tomorrow's targets with tomorrow's intake, so a weekly-mode target already reflects today's eating). Each render arms one **inexact, non-wakeup** `AlarmManager.set(RTC)` alarm for the next local midnight (+5 s) to its own provider (explicit broadcast; no exact-alarm permission, `apk_hardening_check` stays green). The system's boot/update `APPWIDGET_UPDATE` re-arms it. No block for today (app not opened for 2 days) → the plain state ("What did you eat?" + buttons / the mark), never stale numbers. While the app runs, `todayProvider`'s midnight tick rewrites. | Simplest correct; no background Dart |
| D5 | **Writer:** `HomeWidgetCoordinator` (features/home_widgets, started by the bootstrap after account recovery, like notifications) follows `homeWidgetInputsProvider` (generation, today, `dayProvider` + `dayTargetsProvider` for today and tomorrow, the hide setting, `accountStatusProvider`) and writes on every change, coalesced, plus on resume. A **profile generation bump clears at once** (old numbers never shown for the new profile), then the new profile's snapshot follows; inputs of another generation are dropped. A read-only copy (sign-out, keep) → `signedOut`. | UX-084, UX-085 |
| D6 | **Clearing:** `onDeleted` (profile files deleted: sign-out remove, removal, account deletion) calls `homeWidgetStore.clearFor(key)`: clears only when the stored tag is that profile's (the new profile may already have written), next to `exportHandoffs.removeProfile`. Lives in `core/home_widget/` so core doesn't import a feature. | UX-085 |
| D7 | **Taps (UX-083):** explicit `PendingIntent.getActivity` to `MainActivity`, `FLAG_IMMUTABLE`, one fixed action string per target (`…fitnessbuddy.widget.TODAY/ASK/SPEAK/WEIGH`, distinct actions so the PendingIntents never merge). No intent filter added to the activity. `MainActivity` passes only a known action to Dart (launch: taken once; `onNewIntent`: pushed); Dart parses it again against the `HomeWidgetAction` allow-list; unknown → nothing (the app just opens). Routing in one function `homeWidgetRoute`: today → `TodayRoute()`, weigh → `TodayRoute(open: weighIn)`, ask → `TodayRoute(open: buddy)`, **speak → the same as ask until A70's `BuddyEntry` lands (one marked spot: `openBuddyFromWidget`)**. The only new exported component is the three `AppWidgetProvider` receivers (the platform requires export; filter `APPWIDGET_UPDATE` only). | Explicit, allow-listed, no deep links |
| D8 | **Hide numbers:** a synced boolean setting `widgets.hideNumbers` (default off) through `SettingsActions` (a direct action with Undo, like Halal), a switch in Me › Preferences under a "Home-screen widgets" group. ## Outcome

_Built 2026-11-07 on `3eb541ee` (lane 2). Not pushed; merge and the Codex review are the orchestrator's._

**Reviews:** Codex code + security: changes requested (2 majors, 1 medium, 1 low, 2 minors), all fixed in `10832364` and `605433ad`.

**Built:** WP1–WP3 as planned (commits above), WP4 = this card. Size: M.

**How it works:** the app writes a numbers-only snapshot (today's and tomorrow's blocks, a hidden/signed-out state, a hashed profile tag) through an own platform channel into the private `fb_home_widget` preferences file; three RemoteViews widgets draw it and pick the block for the phone's date. Writes follow Today's providers (diary + targets of today and tomorrow), the hide setting, the account status, resume and the midnight tick; a profile switch clears first; profile deletion (sign-out remove, removal, account deletion) clears the deleted profile's snapshot. Each redraw arms one inexact non-waking alarm for the next midnight.

**Deviations:**
- **No bridge plugin** (D1): `home_widget` 0.10.0 checked and not used (Glance, Compose runtime, WorkManager and coroutines for features we don't need); an own ~300-line Kotlin channel and renderer instead. No new pub or Gradle dependency.
- **Fixed widget words are Android string resources** (`values/widget_strings.xml`), not ARB: the launcher shows them before the app ever ran. The numbers and their captions come from ARB through the snapshot.
- **Ask doesn't raise the keyboard yet, Speak opens Buddy like Ask**: both open the Buddy sheet over Today until A70's `BuddyEntry` lands; the one place to switch is `buddyFromWidgetLocation` in `lib/features/home_widgets/application/home_widget_actions.dart` (marked `A70 SWITCH`).
- A read-only copy after sign-out ("keep") shows "Open Fitness Buddy" (no numbers), like a cleared widget; a guest's own numbers show.
- Android only (D-081: the Dart side no-ops elsewhere; iOS widgets need a WidgetKit extension, R2 iOS work).

**Open for the A55 check (exit 1):** the ring/bar drawables and text sizes are untested on a real launcher; widget preview (Android 12+) is the layout with no numbers.
