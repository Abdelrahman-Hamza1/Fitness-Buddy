**Goal.** The app switches from the A02 "Warm" indigo look to the **"Embrace" identity** the owner approved on the design canvas (2026-10-29: "The UI looks amazing"): the Embrace palette (dark "Deep Forest" as the default, light "Mint Cream"), Nunito + Inter typography, the canvas's shape and density, and real branding inside the app: a vector Embrace mark, adaptive launcher icon with an Android 13 themed (monochrome) icon, an Android 12+ splash, the "Fitness Buddy" wordmark and a Buddy avatar. After this, every later screen inherits the identity from tokens, and the phone looks like the canvas.

**Spec:** UX-040 (amended: dark by default, see D-entry), UX-041, UX-042, UX-043, UX-070, UX-071, SF-021 · **Decisions:** TD-014 (design system), A02 D1–D6 (palette parts superseded), backlog #59/#75 (palette pick, superseded by the owner's Embrace pick), #74 (density), the new identity TD

## Scope
1. **Palette.** Replace the values in `packages/fb_design_system/lib/src/tokens/palette.dart` with Embrace light ("Mint Cream") and dark ("Deep Forest") per `../design/embrace/README.md`: brand teal, mint accent, protein moves to **blue**, over-target stays **neutral grey**. Add a `mint` accent role if the plan needs it (Buddy avatar, highlights). Keep and extend the contrast test so every text/control pair passes WCAG AA (UX-071); tune values only as far as AA needs, and list any change.
2. **Theme mode.** **Dark is the default**; the existing Me/Settings "Theme: System / Light / Dark" setting (`SettingKeys.theme`) stays, persisted locally, default `dark`. Only **one brand palette in R1**, but tokens are structured so a second palette is a one-file change (no palette picker UI).
3. **Typography.** Nunito (screen/card titles, big numbers with tabular figures, the wordmark) + Inter (body, labels, buttons, chips), both bundled as variable-font assets (OFL; listed on the licenses page like the existing fonts, with `SOURCES.md` hashes). Noto Sans Arabic stays the Arabic fallback.
4. **Density.** Decide in the plan (owner backlog #74: "a lot of scrolling"): the canvas's **compact** values for Today (card padding 12, gaps 8, rows 44, display number 40) as the default, or justify otherwise.
5. **Shape.** Radii per the identity: cards 20, chips/inputs 12, sheets 28 (top corners), pill buttons. No shadows in dark, no coloured left borders, no gradients.
6. **Branding.** The final Embrace mark as vector, refined from the owner's draft (`../design/embrace/logo-embrace-draft.png`): two colours only (#0B6E5F + #A8E3CB), one stroke weight, wider gaps, fits the Android adaptive-icon safe zone (central 66% circle), plus a one-colour monochrome version for Android 13 themed icons. Ship: adaptive launcher icon (foreground/background/monochrome) for every flavor (dev/staging/prod told apart), the Android 12+ splash (icon + background colour), the wordmark "Fitness Buddy" (Nunito 900) on onboarding/welcome and About/licenses, and a Buddy avatar (small mark) component for the input bar and A22a's chat sheet. The source SVG stays in the repo.
7. **Goldens and tests.** Regenerate every affected golden; Patrol changes only if UI copy changes (grep `patrol_test` for any changed text).
8. **Decision record.** A TD for the identity (palette, fonts, theme-mode default, one-palette rule), superseding the palette parts of A02's decisions; a spec D-entry amending UX-040's default.

### 1. Summary
The design system switches to the Embrace identity at token level: one brand palette (dark "Deep Forest" / light "Mint Cream", with a new `mint` role and Buddy-avatar roles), Nunito + Inter type, the identity's radii, and a **compact density token set**. Component themes carry all of it, so screens inherit it. **Dark becomes the default theme** (setting kept; the first frame and the Android window/splash are dark too). The Embrace mark's geometry lives **once**, as const SVG path strings in `fb_design_system`. A small parser turns them into Flutter `Path`s. The committed SVGs and the Android VectorDrawables (adaptive launcher icon with a monochrome layer, splash) are verbatim copies, and a test checks they match. New DS widgets `FbBrandMark`, `FbBrandLockup` (mark + "Fitness Buddy" wordmark) and `FbBuddyAvatar` appear on the first Setup page, About, the licences page and Today's input bar. Every golden is regenerated. A final **deferred WP** brings A22a in once it's on `main` and wires the avatar into the chat sheet.

### 3. Design

#### 3.1 Tokens & theme (`packages/fb_design_system/lib/src/`)
- `tokens/palette.dart`: new fields `mint`, `avatarBackground`, `avatarForeground`. Values per D1/D2. Doc comment: "Embrace (TD-098)".
- `tokens/colors.dart`: `FbColors` gets `mint`, `avatarBackground`, `avatarForeground` (in `fromPalette`, `copyWith`, `lerp`).
- `tokens/typography.dart`: D4. `textTheme`: `display*` → display, `headline*` → headline, `titleLarge/Medium` → title, the rest as today.
- `tokens/spacing.dart`: `FbRadius.lg = 20`, with doc comments per role. `tokens/density.dart` (new, D6), exported.
- `tokens/contrast.dart`: `fbContrastPairs` adds `avatarForeground on avatarBackground` (ui), `mint on avatarBackground` (ui) and `wordmark (onBrandContainer) on surface` (text). The chip label (`onSurface` on `surfaceContainerHigh`) and the nav label (`onSurfaceVariant` on `surfaceContainer`) are already covered by text × surfaces. `mint` on the surfaces is **not** a pair (decoration, like `outlineVariant`). The doc comment says so and adds that the brand mark/lockup is a logo, exempt from WCAG 1.4.11 (PA8).
